# Бенчмарки FlatMap и FlatMap2

Запуск: `python3 FlatMap/run_benchmarks.py --runs 5 --output FlatMap/benchmark_results/expanded`.
Нужны Python 3 и GCC/Clang с libstdc++; компилятор выбирается через `CXX`.
`pairs` — `FlatMap.h` (вектор пар), `split` — `FlatMap2.h` (два вектора).
Заголовки собираются отдельно, исходники контейнеров не меняются.

## Данные

10 сочетаний ключа и значения: `int/int` и для каждого из трёх типов
`int/T`, `T/int`, `T/T`:

- `int`: обычное целое, 4 байта на этой платформе.
- `struct64`: структура с inline-массивом целых, 64 байта.
- `struct1024`: структура с inline-массивом целых, 1024 байта.
- `class_record`: класс с закрытым массивом 256 байт и `std::string`
  длиной 80 символов. На данной платформе объект занимает 288 байт,
  дополнительная память строки в `sizeof` не входит. Копирование строки
  нетривиально, перемещение класса использует перемещение строки.

Ключи сравниваются по первому целому (ID), а не по всей нагрузке.
Это измеряет влияние размещения данных, не стоимость лексикографического
сравнения больших ключей. Данные воспроизводимы, seed `20260921`.
Размеры контейнера: 256, 4096, 16384 элементов.

## Операции

- `find_hit`, `find_miss`: по 100000 подготовленных случайных запросов;
  успешный поиск читает первое целое значения. Запросы хранятся как полноценные
  объекты ключей, поэтому большие ключи увеличивают также рабочий набор запросов.
- `insert_random`: рост пустого контейнера до N, включая создание аргументов,
  выделения памяти и перемещения. Подготовка случайного порядка вне таймера.
- `erase_random`: уменьшение предварительно заполненного контейнера до нуля;
  создание ключа запроса и освобождение памяти удаляемого значения внутри таймера.
- `iter_keys`, `iter_values`: прямой const-обход с `++` и `->`, чтение только ID.
- `iter_pairs`: range-for с разыменованием proxy и чтением обоих ID.
- `iter_full`: range-for, чтение всех целых и всех символов строк ключа и значения.
- `iter_reverse`: const reverse-обход с чтением обоих ID.
- `iter_random`: `const_iterator::operator[]` по случайной перестановке индексов.
- `iter_mutate`: mutable-обход и увеличение первого целого каждого значения.

Для вставки/удаления N ограничено 4096 из-за квадратичной стоимости сдвигов.
Маленькие контейнеры измеряются несколькими независимыми партиями.
Время этих операций — среднее за рост/опустошение, не при постоянном N.
Для итераторов ns/op означает наносекунды на посещённый элемент.
Обходы повторяются примерно на миллион посещений, минимум четыре раза.
Это стоимость обхода с указанной работой, а не изолированная стоимость `++`.

## Проверки и методика

Перед измерениями каждый заголовок проходит `review_tests.cpp` и
`benchmark.cpp --verify` с ASan, UBSan и `_GLIBCXX_DEBUG`.
Последний проверяет все 10 сочетаний типов при N=1,17,256: пустое состояние,
дубликаты, поиск, арифметику позиций, контрольные суммы всех обходов, запись через
proxy, соответствие ключей и значений после случайных вставок и полное удаление.
Проверки бенчмарка активны также в release и выполняются вне таймера.
Это диагностические тесты измеряемых сценариев, не доказательство полной
корректности контейнера или соответствия итераторов всем требованиям стандарта.

Замеры: `-std=c++20 -O3 -DNDEBUG`, без санитайзеров. GCC/Clang asm-барьеры
сохраняют результаты поиска и повторные обходы; барьер между обходами
позволяет компилятору векторизовать внутренний цикл. Стоимость барьеров входит
в измерения. Первый полный прогон каждой версии — отброшенный прогрев.
Далее пять прогонов с чередованием порядка версий. На Linux процесс закрепляется
за первым разрешённым логическим CPU. Частоты CPU и фоновая нагрузка не управляются.

`raw.csv` содержит отдельные измерения, `summary.md` — медианы ns/op,
CPU, компилятор, флаги, размеры объектов и SHA256 исходников.
`Pairs / split > 1` означает преимущество FlatMap2.
Результаты относятся к повторным обходам подготовленных данных; рабочий набор
может превышать кеш. Малые отличия следует сопоставлять с разбросом прогонов.
Потребление памяти и гарантии исключений здесь не измеряются.
